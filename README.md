# Raabta 0.2 — conversations before connections

Android-first app for adults seeking a serious relationship. Start by talking privately with an AI guide over seven distinct days, review what it understood, approve your own profile, then meet compatible real members only after mutual acceptance.

**Delivery status: upgraded, tested source; not a live production service or signed APK.** Live provider delivery, deployment, real-device testing and store review remain launch gates. See `docs/VALIDATION.md` for exact evidence. There are no fake users, fake live AI responses or invented matches in the shipped service.

## Added in 0.2

- Verified recovery email, expiring single-use codes, resend/attempt limits and password recovery via Resend.
- Password change, session revocation and sign-out of all devices. Existing pilot accounts can add their recovery email in You.
- Read and correct the AI's private rolling memory; updated instructions prioritize corrections.
- OpenAI moderation checks on AI inputs/outputs, shared profile text and partner messages; failures stop delivery instead of silently bypassing safety. Personal distress can still be discussed with the guide.
- Report individual AI replies for operator review, alongside existing partner report/block controls.
- Unread counts, read cursors, earlier AI history loading and bounded AI context queries.
- Block/unblock management. Unblocking never reopens old conversations.
- Versioned consent records; verified-email gating for AI and new matching.
- Browser account deletion, hosted privacy notice and community rules.
- Production configuration validation, HTTPS reverse proxy, single-instance deployment configuration, encrypted-field database backups with restore test, and CI checks.

Matching remains explainable rules based on **approved** values, interests, communication preferences and bilateral dealbreakers. It is not a scientifically validated compatibility score. AI helps reflect and draft; it does not secretly judge intimate conversations to rank partners. No raw private AI history or memory is included in another user's profile.

## Local setup on Windows

Install Node 24. Extract the ZIP. In PowerShell:

```powershell
cd path\to\raabta\server
npm run setup
notepad .env
```

Fill `OPENAI_API_KEY`, `OPENAI_MODEL`, `RESEND_API_KEY`, and `MAIL_FROM` from a verified sending domain. Keep secrets in this **server** file only. The model must support the Responses API and strict JSON schema. `DATA_KEY` and invitation code are generated by setup. Back up the key securely: losing it loses access to encrypted data.

```powershell
npm test
npm start
```

In a second terminal:

```powershell
cd path\to\raabta\mobile
npm ci
Copy-Item .env.example .env
notepad .env
```

Set `EXPO_PUBLIC_API_URL=http://YOUR-PC-LAN-IP:8080`, then:

```powershell
npx expo start --clear
```

Use the same Wi-Fi and an Expo Go/dev build compatible with SDK 57. `localhost` on a phone is the phone itself. HTTP works only in development. Production builds reject HTTP.

Create an account, open **You**, send the email code and verify it, then start conversations. A qualifying day is two messages of at least 40 characters each and 120 characters total. The server counts distinct India-calendar days. This is a product rule, not a scientific readiness assessment.

Do not disable verification/moderation on a public server. Tests inject synthetic providers and never call paid services. Normal development defaults still require real providers.

## Deploy with HTTPS

A complete one-process Node/SQLite + Caddy setup is in `deploy/`. Use a persistent Linux host with Docker Compose, a domain pointing to it, and inbound ports 80/443. Do not expose API port 8080 publicly or run multiple API replicas.

1. Copy `server/.env` with its existing DATA_KEY to the host securely.
2. Set `NODE_ENV=production`, `PUBLIC_ORIGIN=https://api.your-domain.com`, `SUPPORT_EMAIL` and `OPERATOR_NAME` plus the provider credentials. Keep `REQUIRE_EMAIL_VERIFICATION=true` and `MODERATION_ENABLED=true`.
3. Copy `deploy/.env.example` to `deploy/.env`; set `API_DOMAIN=api.your-domain.com`.
4. From `deploy/`, run `docker compose up -d --build`.
5. Check `/health`, `/privacy`, `/terms` and `/delete-account` on your HTTPS origin.
6. Send a real verification email, reset a test account password, complete a real AI conversation and test two accounts before inviting anyone.

The startup guard refuses production without required credentials and contacts. It checks presence/configuration, not credential validity. The included privacy notice/community rules must reflect the operator's actual practices before publication.

### Backups and recovery

From `deploy/`:

```sh
docker compose exec -T -e BACKUP_DIR=/backups api node backup.mjs
```

Schedule this at least daily on the host. The command makes an online SQLite snapshot, checks integrity and prunes snapshots older than 7 days. Transfer snapshots to encrypted off-host storage with the **same seven-day expiry**. Snapshot account metadata is not whole-file encrypted; use encrypted storage. Keep DATA_KEY in a separate secret store. Do not copy only the live `.db` file while WAL writes are active.

To restore: stop API writes, retain the damaged database separately, restore a verified snapshot and its matching key, remove obsolete WAL/SHM companions while stopped, test in isolation, replay any deletions made after the snapshot, then bring the API online. Do not blindly restore previously deleted users. See `docs/OPERATIONS.md`.

## Build APK and Play Store AAB

In `mobile/`, under **your** Expo account:

```powershell
npx eas-cli@latest login
npx eas-cli@latest init
npx eas-cli@latest env:create --environment preview --name EXPO_PUBLIC_API_URL --value https://api.your-domain.com --visibility plaintext
npx eas-cli@latest env:create --environment production --name EXPO_PUBLIC_API_URL --value https://api.your-domain.com --visibility plaintext
npx eas-cli@latest build --platform android --profile preview
```

Preview produces an installable APK. After physical-device tests:

```powershell
npx eas-cli@latest build --platform android --profile production
```

Production produces an AAB for Play Console. EAS signing stays in your account. Current package is `com.satyammishra.raabta`; decide the final identifier before your first publication. Android bundle export passing is **not** proof that an APK installs or works on a phone.

## Operator moderation

Inside the API container or configured `server/` directory:

```sh
node --env-file=.env admin.mjs reports
node --env-file=.env admin.mjs suspend USER_ID
node --env-file=.env admin.mjs resolve REPORT_ID
node --env-file=.env admin.mjs resolve-ai AI_REPORT_ID
```

In Docker, use `docker compose exec -T api node admin.mjs reports` (environment is already supplied). Keep operator access private. Review reports routinely; automated moderation is not identity verification or a replacement for human review.

## Remaining public-launch work

- Live provider credentials, sending domain, HTTPS host, and actual API usage/budget monitoring.
- Signed APK/AAB and two physical Android devices for backgrounding, relaunch, keyboard, offline retry, account recovery and block/report tests.
- Staffed safety/support processes, identity/age-abuse handling, privacy/terms review and store disclosures.
- Load/cost testing before a larger rollout. This implementation intentionally runs one API process with SQLite and in-process locks; it is not horizontally scalable as shipped.

This version is text-first. It does **not** implement profile photos/liveness verification, voice/video calls, push notifications, subscriptions or payments. Partner chat polls while the app is foregrounded. Email verifies inbox ownership, not age or identity. Names are not trademark-cleared. Nothing has been purchased, deployed, signed or uploaded to Play Console by this source delivery.
